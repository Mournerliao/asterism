# 2026-07-28 · 自然 AI 整理产品研究

## 背景

再次从重度 Star 用户视角审视当前 AI 整理：用户必须先进入批量模式，手动选择或构造筛选范围，且单次最多处理 50 条，再逐仓库审阅完整建议表。实现虽可靠、可恢复且安全，但没有替用户承担历史大库中最困难的范围判断与分批计划。

## 本轮完成

- 重构 ADR 0020、0023、0025、0026、0027、0028 的决策链，区分已被真实库否定的全库互斥分簇 / promotion / 二维星图，与仍应坚持的 canonical / derived 分离、BYOK、人工授权和可靠批量执行。
- 评估新用户历史大库、已有组织结构的持续维护用户，以及只想重新找到仓库而不愿整理的用户旅程。
- 调研 PIM 原始研究及 GitHub Lists、Raindrop.io、Readwise Reader、myMind、Notion AI、Apple Photos、Google Photos 的一手产品资料，记录摄取、派生元数据、长期结构写入、纠错、渐进维护、规模与隐私边界。
- 研究阶段收敛出待用户确认的建议方向：从 selection-first 批处理改为 intent-first planner。用户表达结果，系统用 derived 能力发现并解释完整候选范围，内部按 Provider 安全边界有界分页，用户只审阅真正带长期语义或破坏风险的聚合动作，最终复用 ADR 0023 批量账本。

## 研究阶段边界

研究完成时只形成产品提案，没有修改产品 / UI / 架构 / 数据契约，没有新增 ADR，也没有实施新整理入口。尤其没有把此前讨论过的 recent / unorganized Review Queue 当作已决定功能。是否允许用户授权的全库范围发现、内部隐式分页与任务级草稿，当时仍需用户明确选择后再更新契约。

完整证据与比较见 `knowledge/research/2026-07-28-natural-ai-organization.md`。

## 后续确认（同日）

用户在 `grill-with-docs` 产品访谈中确认了五项高层原则：同步后可以出现可忽略、无 BYOK 成本的整理机会；首次同步建立初始秩序，后续同步渐进维护；canonical 结构围绕用户用途而非模型臆造的天然主题；审阅粒度按加入已有分类、新分类和移除关系的风险区分；每个已执行任务都支持任务级撤销。

据此新增 Accepted ADR 0029，并同步 `product.md`、`ui-ux.md`、`architecture.md`、`data-model.md`、路线图与 Web 产品摘要。产品方向已足够进入原型和规格阶段，但本轮仍未设计数据库字段、最终任务状态机或生产 UI，也没有修改代码；这些细节必须由真实个人库原型回答。
