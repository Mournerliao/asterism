# 2026-08-06 · Collection Dial 产品对齐

## 背景

AI 整理在真实使用后已按 ADR 0032 完整退役。新的探索不恢复 Provider、Generation、Organization Task 或自动整理，而是把浏览器内语义能力限制在一个更窄的职责：用户直接整理仓库时，把更可能的既有集合送到手边。

## 核心模型

- 正式工作术语为 **集合盘（Collection Dial）**；「建议集合」只描述候选状态，「语义」和「AI」不进入用户功能名。
- 用户从 Browse 卡片或列表行直接拖动仓库，越过阈值后底部临时出现弧形集合盘；它不是新页面或持久整理模式。
- 一个 active 集合居中，左右各显示两个相邻目标。左手 `Q` / `E`、鼠标与纯键盘路径操作同一个 active 状态，序列不循环。
- 快速序列最多包含 5 个已有集合，另有「更多集合」与「新建集合」；二者冻结当前仓库范围并承接选择或创建，创建成功后自动加入。
- 正常浏览拖动单项；已进入选择模式且拖动已选项时才携带整个稳定选择范围。一次拖拽只加入一个集合，多选投放后保留原选择范围。
- 功能只处理集合，不把标签塞入同一空间隐喻。首个原型与实现切片只覆盖 Browse。

## 推荐边界

- 推荐预测用户当前最可能选择的集合，不等同于纯内容相似度；信号可包含本地语义近邻、既有关系与当前会话最近使用。
- 单项排除已经加入的快速目标；多选以各仓库候选的共识投票排序，不平均异质范围。无清晰共识时不显示语义建议。
- 候选在拖动开始时形成快照，并在整个手势中冻结。第一候选默认 active；无有效候选时由「更多集合」或「新建集合」承接。
- embedding 未启用或未就绪时不在拖动中打断用户，而是静默降级为最近使用与稳定顺序。空集合可用名称和描述的本地 embedding 以较低权重参与。
- 不新增推荐接受 / 拒绝行为日志，不重新引入生成式模型、Provider 或 BYOK。高置信候选最多显示克制的「建议」状态和可验证近邻理由，不使用 AI / Sparkles 标记。

## 输入、写入与恢复

- 桌面端可从非交互背景越过位移阈值启动，hover / focus 时显示 Grip 暗示；移动端以常驻 Grip 为唯一拖动起点，并保留点按等价路径，不使用整卡长按。
- 纯键盘使用 Space 拿起、Q/E 转动、Enter 投放、Escape 取消，并以 ARIA live 播报范围、active 目标及写入状态。
- 只有在集合盘投放区内松开才提交；盘外松开或 Escape 取消。
- Drop 是用户确认，但界面等待服务端权威成功后才宣告完成。失败保留范围与目标并允许重试或取消。
- 每次成功形成独立短期 Undo；连续通知可以聚合展示，但 Undo 不得被偷换成整段会话回滚。
- 已有关系按幂等语义处理。多选部分已加入时只新增缺失关系，并准确披露新增与已有数量。
- 未完成批量操作期间阻止新的多选拖放，但不锁死普通单仓库拖放。

## 原型门槛

下一阶段先做 throwaway UI prototype，使用内存状态和假推荐，不接真实数据库、embedding 或生产写入。三种变体共享同一状态机，只比较浅弧卡槽、Dock 纵深和明显轮盘的空间表现。

原型必须通过真实连续操作形成 verdict：桌面连续处理 10 个仓库，移动端连续滚动并处理 5 个仓库；检查误开 Quick Look、误投放、Q/E 命中、拖拽 / 滚动冲突、更多 / 新建承接，以及 pending、failure、retry 和指定单次 Undo 是否容易理解。原型通过前不更新正式产品契约、不创建新 ADR，也不进入生产实现。

## Throwaway UI prototype · 2026-08-06

已在现有 Browse 路由加入开发态原型入口：`/?prototype=collection-dial&variant=A|B|C`。原型使用内存假数据与假写入，不触碰数据库、embedding 或生产 mutation；可点击或拖拽仓库，使用 Q / E、方向键或盘面按钮改变 active 集合，模拟 drop 的 pending / failure / retry，以及独立单次 Undo。

三种结构：A「浅弧卡槽」（Browse 表面内联）、B「Dock 纵深」（右侧固定承接区）、C「明显轮盘」（高辨识轮盘）。底部切换器通过 URL 参数保持可分享，生产构建不挂载。尚未执行原型门槛中的连续桌面 / 移动实测，因此没有形成产品 verdict；下一步是按上方验收清单实测并只保留验证后的结论。
