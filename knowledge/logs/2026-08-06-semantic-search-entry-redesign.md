# 语义搜索入口重设计

日期：2026-08-06

## 背景

原 embedding 准备提示位于 Browse 筛选栏与仓库结果之间。即使压缩为无背景、无边框的紧凑行，它仍打断主要浏览任务，并把可选能力错误提升为页面级状态。

## 落地

- 删除 Browse 内容流中的 `EmbeddingPreparationBanner`。
- 用户在 Browse 全局搜索框输入后，才显示一次轻量搜索浮层，解释「按含义查找」、一次性约 120 MB 下载与纯浏览器处理。
- 「暂不」只关闭发现提示，按账号与固定模型持久化；不撤销能力，也不影响 Settings 永久入口。
- opt-in 后的检查、模型下载、回填进度与 degraded 重试继续显示在搜索浮层中。
- Settings 新增「搜索 / 语义搜索」管理区，覆盖未启用、准备中、已就绪与 degraded 四类状态，并提供启用、重建索引、清理模型。
- 清理模型需二次确认，同时删除本人派生向量、浏览器模型缓存与 opt-in；关键词搜索始终保留。
- embedding bootstrap 从 Browse 页提升为 AppLayout 级共享 provider，避免搜索浮层、Settings 和 Browse 各自创建准备任务。
- en / zh-CN 文案同步更新。

## 验证

- Biome 对本次涉及的 12 个现存源码与 locale 文件检查通过并完成格式化。
- Web TypeScript `--noEmit` 检查通过。
- 按用户要求未启动浏览器、未执行视觉 QA；交由用户实测交互与视觉效果。

## 输入焦点修正

用户实测发现发现浮层打开时 Radix Popover 的默认 auto-focus 会把焦点从搜索框移入浮层。现已在该浮层打开事件中显式阻止自动聚焦，使浮层保持被动展示，连续键盘输入不再中断；按钮仍可通过 Tab 正常到达。新增组件回归断言锁定「浮层出现后搜索输入框仍为 activeElement」。

## 输入响应优化

用户继续实测发现搜索输入反馈不够顺滑。诊断确认语义查询已有 180ms debounce，并非逐键执行；实际阻塞来自 Zustand query 更新后，Browse 在与受控输入相同的渲染优先级中同步筛选、排序并更新虚拟列表。现以 `useDeferredValue` 分离即时输入值与结果查询值：搜索框保持逐键即时提交，关键词排名、结果列表和后续语义查询消费 deferred query。其余 facet 与排序仍即时生效，搜索语义不变。
